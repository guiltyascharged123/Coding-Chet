# Evaluate a model before giving it a large project

Twenty role templates provide methods and responsibilities; they do not create twenty separately trained experts. Use the same small briefs when comparing models. Begin with concurrency one, automatic meetings off and a deliberate request limit. Keep paid APIs disabled unless you explicitly want to measure them.

## Repeatable acceptance cases

| Case                       | Brief and success check                                                                                                                                                                                                                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Arithmetic and uncertainty | “Compare office A at $20/month and B at $35/month for 12 months. I have supplied no customer research. Recommend a reversible next step.” Expect $240/$420 annual costs, $180 annual difference, explicit uncertainty and no invented research or transactions.                                                 |
| Planning and coordination  | “Plan delivery of a meeting-notes tool using supplied sample notes. Define useful outputs and acceptance checks. Do not publish or contact anyone.” Expect bounded, dependency-correct tasks with owners and relevant outputs; routine planning should not require human approval.                              |
| Retained direction         | Save standing directions “no spending” and “use only supplied evidence.” Add later questions and reject a specific approach on the board. Ask for a revised plan. Expect both active directions to remain and the rejection to be considered; revoke one and verify the distinction in the next public request. |
| Internal handoff           | Ask the coordinator to obtain a specialist check of a specific cost calculation. Expect a focused assignment with acceptance criteria, the actual result used in the reply, and a visible dependency/retry link if it fails. No invented colleague response.                                                    |
| Software delivery          | With ready Codex tools, request a local CSV expense summarizer with invalid-row handling, sample input, tests and usage instructions. Expect actual files, meaningful passing tests and a separate reviewer. Manually check an invalid amount and an empty CSV. A report without files is not delivery.         |
| Failure and recovery       | In a disposable project, pause an active job or disconnect its configured local provider. Expect a saved failure without fabricated output or silent provider fallback. Restore the connection, review Usage/files and retry the same task. Check that completed work was not deleted.                          |
| Meeting accountability     | Invite two specialists to challenge a concrete proposal. Expect two role-specific contributions and a chair, task-linked actions and explicit unresolved objections. Only accepted target-task checks can resolve assigned actions.                                                                             |

Use supplied material for reproducible research checks. If testing live web research, record the query/date and verify primary-source URLs yourself. Text-only adapters cannot browse just because an agent is named Researcher.

## Record what happened

For each case, record exact connection/model ID, reasoning setting, input/output limits, run date, elapsed time, request count, format corrections, retries, unnecessary human interruptions, unsupported claims and whether the deliverable passed the checks above. Export the relevant output and public console after reviewing it for sensitive project details.

Score usefulness from 0 to 3: **0** failed/fabricated; **1** readable but materially wrong or unusable; **2** useful after corrections; **3** correct and usable on the first accepted result. Record failure reasons, rather than averaging them away. Compare cost and time per **usable result**, not per response. Codex subscription allowance is not a dollar estimate and is not visible to Workroom; API receipts are estimates/confirmed usage where available.

Run the checks again after changing a model or major prompt contract. A connection's green status proves readiness checks, not task quality. A small local model may be suitable for narrow office tasks while failing complex planning or tool use. Choose based on measured results; do not assume a larger model or a more elaborate agent title guarantees success.

These are opt-in live checks. The repository's automated model fixtures test control flow and protocols without consuming inference allowance; they are not published live benchmark scores.
